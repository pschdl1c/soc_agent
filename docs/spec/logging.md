# Логирование

**Модуль:** `app/logging_setup.py`
**Назначение:** один раз настроить вывод логов приложения так, чтобы он был читаем при любом
способе запуска — в консоли и при перенаправлении в файл.

## Область ответственности

- `configure(level)` — идемпотентная настройка логгера `app` (хендлер, формат, уровень).
- Никаких импортов из `app` (лист-модуль): его зовёт `app/main.py`, а пользуются им все
  модули через штатный `logging.getLogger(__name__)`.

## Проблемы, которые он закрывает

**1. Нечитаемый лог.** `print()` пишет в кодировке потока вывода. На Windows это кодировка
консоли (`cp1251`/`cp866`), поэтому при `uvicorn app.main:app > server.log` русские сообщения
в файле нечитаемы. Это касается в том числе сообщения об ошибке обработки батча в
`app/ingest_queue.py`, на котором держится диагностика потери событий потокового ingest.

**2. Падение детекта из-за одного символа прогресс-бара.** Zircolite рисует прогресс
компиляции правил через `rich` — спиннер `⠋` (U+280B) в `stdout`. Если `stdout` в `cp1251`
(перенаправление в файл, запуск службой, обычная консоль Windows), запись этого символа
бросает `UnicodeEncodeError` ВНУТРИ конвертации: Zircolite ловит его как «Cannot convert» и
отдаёт ПУСТОЙ рулсет. Наружу это выглядит как `«Правило не скомпилировалось в SQL — проверь
detection/logsource»` на заведомо корректном правиле, а на потоковом ingest — как потеря
ЦЕЛОГО флаша (исключение прилетает в `IngestWorker._flush`). Поэтому `configure()` переводит
в UTF-8 ОБА потока, а не только тот, куда пишет наш хендлер.

## `configure(level: str | int = "INFO") -> logging.Logger`

Настраивает логгер с именем `app`:

| Свойство | Значение |
|---|---|
| Потоки | `sys.stdout` И `sys.stderr` переводятся в UTF-8 (`reconfigure(encoding="utf-8", errors="replace")`) |
| Хендлер | `logging.StreamHandler` поверх `sys.stderr` |
| Формат | `%(asctime)s %(levelname)-7s [%(name)s] %(message)s`, дата `%Y-%m-%d %H:%M:%S` |
| `propagate` | `False` |
| Уровень | аргумент `level` (строка приводится к верхнему регистру) |

Повторный вызов — no-op (флаг модуля `_configured`), возвращает тот же логгер.

Поток без метода `reconfigure` (подменённый в тестах, обёрнутый) используется как есть;
ошибка `reconfigure` (`ValueError`/`OSError`) подавляется — логирование важнее кодировки.
`errors="replace"` принципиален: ни один вывод не должен уметь уронить процесс из-за символа,
которого нет в кодировке потока.

`_reset()` — тест-хук: снимает отметку «уже настроено».

## Использование

```python
# в любом модуле app/
import logging
logger = logging.getLogger(__name__)   # имя вида "app.ingest_queue"
logger.info("воркер запущен (batch_size=%s)", batch_size)
```

`configure()` вызывается один раз в `app/main.py` на импорте модуля — ДО создания
`ZircoliteEngine`/`Store`, чтобы первое же сообщение (загрузка рулсета) ушло в UTF-8-хендлер.

Имена логгеров начинаются с `app.`, поэтому все они наследуют единственный хендлер логгера
`app`. `propagate=False` отключает дальнейшую передачу записей root-логгеру: вывод не
дублируется хендлерами uvicorn и не зависит от того, настроил ли кто-то root.

Логгер `app` без вызова `configure()` (импорт модуля в тестах, отдельный скрипт) хендлеров не
имеет — записи уровня `WARNING` и выше уходят в `logging.lastResort`, остальные подавляются.

## Конфигурация

`SIEM_LOG_LEVEL` (`app/config.py` → `config.LOG_LEVEL`, по умолчанию `INFO`).

## Инварианты

- В `app/` не используется `print()` — только логгеры.
- `configure()` вызывается ДО первого обращения к Zircolite (компиляция рулсета) — иначе
  проблема 2 успевает выстрелить.
- Уровни: `info` — штатные события жизненного цикла (старт/остановка воркера, загрузка
  рулсета, результат ретеншна); `exception` — подавленные исключения фоновых задач (сообщение
  плюс трассировка).
