Подробнее ▾
Условие

поле оператор значение — поле обычно совпадает с именем поля в сыром JSON события (регистрозависимо!), либо это одно из специальных полей результата детекта (см. ниже).

Операторы сравнения
  • = / != — точное совпадение / несовпадение
  • > < >= <= — сравнение; если значение похоже на число — сравнение числовое, иначе строковое
  • contains — значение встречается как подстрока (регистрозависимо)
  • in (a, b, c) — поле равно одному из значений списка (через запятую)
  • is null — поля нет в событии; is not null — поле присутствует
Логика и группировка
  • and, or, not — приоритет как в SQL: not сильнее and, and сильнее or
  • a or b and c равносильно a or (b and c) — если нужно наоборот, скобки обязательны: (a or b) and c
  • Скобки можно вкладывать сколь угодно глубоко
Значения
  • В кавычках — "текст со пробелами" или 'текст'; кавычку внутри и обратный слэш экранируют бэкслешем: \", \\
  • Без кавычек — одно слово без пробелов/скобок/кавычек/операторов: числа (4688), простые идентификаторы, хосты вида a.b.local
Поля события

Имя — как в сыром JSON конкретного источника (EVTX/Sysmon/JSON по-разному называют одно и то же: Hostname, Computer, host...). Регистр важен. Если не уверен, как называется поле — открой сырое событие (клик по строке) и посмотри ключи.

Поля результата детекта (не из raw_json)
  • rule — название сработавшего Sigma-правила: = != contains in(...) is null (ничего не сработало) is not null (сработало хоть что-то). А > < >= <= у этого же поля — сравнение не имени, а количества сработавших правил: rule > 1 — сработало больше одного правила
  • is_matched — сработало ли хоть одно правило. Только =/!=, значение true/false (или 1/0)

Те же имена (включая rule/is_matched) работают и в поле "Группировать по полю" — клик по значению группы сужает текущий фильтр (drill-in).

Примеры
  • EventID = 4688
  • Hostname contains "WORKSTATION5"
  • EventID in (4688, 4690, 4656)
  • CommandLine is not null
  • (EventID = 4688 or EventID = 4690) and Hostname contains "DC"
  • is_matched = false and Hostname contains "WORKSTATION"
  • rule contains "HackTool" and not Hostname contains "DC"
  • rule > 1 — сработало больше одного правила
Ошибки

При неверном синтаксисе запрос не выполняется — под строкой фильтра появится точное описание проблемы с позицией символа, на котором споткнулся разбор.
